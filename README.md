这是 GitHub Pages 使用的网页发布文件。发布后的访问地址为：

**https://bu-qi.github.io/cct-qki-tools/**

## 免费页面功能

- CCT 全网剩余算力、地址排名及算力占比。
- CCT 总供应量、累计销毁量，以及产出、燃烧后的整体数据模拟。
- 地址搜索、排序、历史快照及 CSV 导出。

以上 CCT 功能继续免费使用，不需要会员或连接钱包。打开页面立即显示已核验榜单，再轻量读取主站共享快照；不会在进入页面时自动逐地址扫描。快照始终带有区块和时间，搜索、排序及导出可以直接使用。

「更新快照」使用主站持久化的共享任务；多个访客共用一份结果，更新期间仍可查看已有榜单。任务可暂停后继续，只有同一区块的全部地址结果通过核验才整体发布。页面关闭后不会自动定时扫描。共享接口仅含公开 CCT 数据，GitHub Pages 使用固定主站 URL 且不携带登录凭据。

「重新核验全网」保留浏览器完整扫描，点击后才通过以下两个公开 QKI RPC 读取规范区块并核对地址算力与全网总量：

- https://rpc1.qkiscan.io/
- https://hz.rpc.qkiscan.cn/

为减少慢节点造成的等待，首选节点约 1.5 秒内尚未返回完整有效结果时，页面会提前请求备用节点，并在后续批次优先使用成功响应的节点；首选节点明确失败时立即切换尝试。首选节点及时响应时不会额外请求备用。

参与地址日志从每段 1,000 个区块开始读取，减少大段日志下载后再拆分重读的等待。遇到日志过多或节点区间限制时仍继续拆分，不跳过任何应覆盖的历史区块。

查询仍会读取全部历史候选地址，并将每个地址的算力锁定在同一区块哈希下。只有区块、合约实现以及全部地址算力之和与合约总算力通过核验，才显示完整榜单；不会通过省略地址或混用旧算力来缩短等待。

节点不可用或核验失败时，页面会显示状态，不会把历史快照标成实时结果。产出与燃烧模拟的规则及假设见页面说明。
